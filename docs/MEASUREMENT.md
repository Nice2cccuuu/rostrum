# Measurement: capacity is measured, never guessed

Every overflow defect in an automated slide tool traces to the same root cause:
**something wrote text into a box without knowing how much the box holds.**
`python-pptx` performs no text measurement — it drops a string into a fixed frame
and assumes it fits. Beamer will silently emit an overfull box. So the tool must
measure for itself.

## Why the common heuristic fails

The usual shortcut is "a CJK character is about two Latin characters". Measured
against Noto Sans CJK:

| Character | Advance (em) |
| --- | --- |
| `研` (ideograph) | 1.000 |
| `，` (fullwidth comma) | 1.000 |
| `W` | 0.878 |
| `A` | 0.608 |
| `1` | 0.555 |
| `i` | 0.275 |
| space | 0.224 |

Two conclusions:

- An ideograph is **1.70x** the mean Latin advance, not 2.0 — a 15% error, which
  compounds across a full slide.
- Latin advances vary **3.19x** between `i` and `W`. No single ratio can stand in
  for measurement, because the error depends on what the author happened to
  write.

Getting this wrong in the optimistic direction is the harmful case: the planner
believes a box holds more than it does, and the deck overflows.

## Advance widths

`FontMetrics` reads the font's `hmtx` table via `fontTools` and normalises by
`unitsPerEm`, caching per codepoint. `.ttc` collections are indexed. When no
font file is available it falls back to constants derived from Noto averages —
accuracy degrades, nothing breaks.

```python
from rostrum.measure import load_font

font = load_font("/usr/share/fonts/opentype/noto/NotoSansCJK-Regular.ttc")
font.measured               # True when real glyph data backed it
font.advance_em("研")       # 1.0
font.string_width_pt("研究方法", 20.0)   # 80.0 pt
```

## Line breaking

CJK and Latin break by different rules, and a real renderer applies both:

- **Latin** breaks between words; a token wider than the box is split mid-token.
- **CJK** breaks between characters, subject to *kinsoku shori*:
  - closing punctuation (`，。、；：？！）」`) may not begin a line — it is pulled
    up onto the previous line;
  - opening punctuation (`（「《`) may not end a line — it is pushed down.

A line starting with a comma is immediately visible to any reader, so these are
tested as invariants across many box widths rather than spot-checked.

```python
wrap_text("这是一个测试，用于验证换行规则。", width_pt=120, font_size_pt=20, font=font)
# ['这是一个测试，', '用于验证换行规', '则。']
```

## Capacity as a sound upper bound

`capacity_units()` answers: *how many budget units does this box hold at this
size?* The planner treats the answer as a hard constraint, so an optimistic
answer is worse than no answer at all.

Two stages:

1. **Analytic estimate** — available lines x characters per line, from the
   measured mean advance of representative text in the target language. English
   divides by 6.1 (mean word length including its space) because a budget unit
   is a word.
2. **Verification** — binary-search the candidate downward, wrapping
   representative filler text of exactly that size with the *same* wrapping code
   the renderer uses, until it demonstrably fits.

Stage 2 exists because word-wrapped Latin leaves ragged right-edge slack that no
closed form captures. Before it was added, English capacities overflowed by
24–33%; the analytic estimate for one box was 100 words where only 77 fit.

The invariant is tested across 8 box geometries x 2 languages:

> Text filled to exactly the reported capacity must fit.

## Line spacing

| Script | Multiple of font size |
| --- | --- |
| Latin | 1.20 |
| CJK | 1.42 |

CJK needs more because ideographs fill the em box completely, leaving no natural
interline gap.

## Overflow as a continuous metric

`measure_text()` returns `overflow_ratio = used_height / available_height`. A
ratio rather than a boolean, because the CI metric needs a magnitude:

```python
m = measure_text(text, width_pt=300, height_pt=100, font_size_pt=20, font=font)
m.fits              # overflow_ratio <= 1.0
m.overflow_ratio    # 1.65 — badly over, not marginally
```

A deck's **overflow rate** is the fraction of slides with at least one
overflowing slot. Target: 0.

## Autofit is not a solution

PowerPoint's autofit flag is unreliable when set programmatically: the stored
setting is not honoured until the file is opened and the shape re-laid out, which
is why decks generated by other tools look correct in a viewer and wrong in
PowerPoint. Rostrum therefore computes the fit itself and applies an explicit
font size.

Shrinking stops at `Slot.min_font_size_pt` (14pt for body text, 24pt for
titles). Past that the slide is reported as overflowing rather than shrunk
further — **an unreadable slide is not a fixed slide**, and the back row of a
lecture hall cannot read 9pt.

## Template ingestion

Placeholder geometry on a layout is frequently *inherited* from the slide master;
reading `ph.left` naively returns `None`. Resolving the inheritance chain matters
because an unresolved box measures as zero capacity, which would make the planner
reject every slide. `IngestReport.unmeasured_slots` must be 0 for a template to
be trustworthy.

Font size is also often undeclared. Applying PowerPoint's default (44pt for a
title) to a deliberately short title bar would measure it as holding zero lines,
so the ingester instead derives the largest size at which one line fits, floored
at the legibility minimum.

```bash
rostrum inspect lab-template.pptx
```

```
title-and-content
  roles: text_dense, agenda, summary, equation, text_figure, table
  ph0      title      44.0pt     14 units / 1 lines
  ph1      body       18.0pt    455 units / 13 lines
```

## Where measurement enters the pipeline

```
template ─► ingest ─► Slot.capacity_units ─┐
                                            ├─► allocate(deck, capacity=...)
duration + density ─► time budget ─────────┘        │
                                                     ▼
                                        min(time budget, measured capacity)
```

Geometry outranks the clock: a generous time budget must not write 300 characters
into a box proven to hold 130. The surplus becomes narration rather than
overflow, so tightening a slide lengthens the script instead of losing content.

**Bind before allocating** — the allocator needs the chosen layout's capacity,
and the layout is chosen by binding.
